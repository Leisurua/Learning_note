
# CPU如何执行程序


## 图灵机与冯诺依曼结构

图灵机用纸带、读写头和内部状态描述计算过程。

现代计算机主要采用冯诺依曼模型，包括：

运算器（ALU）：执行加减、逻辑运算等。
控制器（CU）：解析指令，控制执行。
存储器：保存程序和数据。
输入设备：向计算机提供信息。
输出设备：输出计算结果。

CPU 内部还有寄存器，用来暂存计算数据、指令和地址。

![[Pasted image 20261021193157.png]]

CPU分为32位和64位

- 32 位 CPU 一次可以计算 4 个字节；
- 64 位 CPU 一次可以计算 8 个字节；

所以32位CPU最多支持4GB 更高的只能支持64位

### 寄存器

通用寄存器：存放要运算的数据

程序计数器（PC）：下一条要执行的指令所在的内存地址 可以参考[[三种视角的OS]]的状态机来理解

指令寄存器（IR）：当前指令

### 总线

地址总线：用于指定CPU将要操作的内存地址

数据总线：用于读写内存的数据

控制总线：用于发送与接收信号

CPU 通过程序计数器读取对应内存地址的指令，这个部分称为 Fetch（取得指令）； 
CPU 对指令进行解码，这个部分称为 Decode（指令译码）； 
CPU 执行指令，这个部分称为 Execution（执行指令）； 
CPU 将计算结果存回寄存器或者将寄存器的值存入内存，这个部分称为 Store（数据回写）；

## Cache Line

一个内存的访问地址，包括组标记、CPU Cache Line 索引、偏移量这三种信息，于是 CPU 就能通过这些信息，在 CPU Cache 中找到缓存的数据。而对于 CPU Cache 里的数据结构，则是由索引 + 有效位 + 组标记 + 数据块组成。

![[Pasted image 20261021195034.png]]


Tag：记录这条缓存数据对应哪个内存地址区域。
Valid Bit：表示该缓存位置中的数据是否有效。
Data：保存从内存取来的实际数据。
Dirty Bit：在采用写回策略的缓存中，表示数据是否已被修改、尚未写回下一级存储。

类似于一个简化的C结构体
```c
struct CacheLine {
    bool valid;
    bool dirty;
    uint64_t tag;
    unsigned char data[64];
};
```


## 地址映射

| 映射方式  | 含义              | 特点       |
| ----- | --------------- | -------- |
| 直接映射  | 每个内存块只能放在指定位置   | 简单，容易冲突  |
| 全相联映射 | 可以放在任意缓存行       | 灵活，查找成本高 |
| 组相联映射 | 指定一个组，组内有多个可选位置 | 折中方案     |

一般有这三种Cache的地址映射

现代CPU Cache常采用组相联

```
CPU Cache
│
├── Set 0（组）
│   ├── Way 0 → Cache Line
│   ├── Way 1 → Cache Line
│   ├── Way 2 → Cache Line
│   └── Way 3 → Cache Line
│
├── Set 1
│   ├── Way 0 → Cache Line
│   ├── Way 1 → Cache Line
│   ├── Way 2 → Cache Line
│   └── Way 3 → Cache Line
│
└── Set N
    └── ...
```


## 局部性原理

时间局部性：最近访问过的数据，可能很快再次访问。

空间局部性：访问某个地址后，可能继续访问附近地址。


# CPU缓存一致性

多个 CPU 核心有各自的缓存，因此可能保存相同内存地址的数据副本。

这个就是解决有关于写入的问题

而对于缓存一致性问题 有写传播和事务的串行话两种 分布对应着总线嗅探与MESI协议

## 写入

写入有两种策略：写直达和写回

### 写直达

也就是**把数据同时写入内存和 Cache 中**

![[Pasted image 20261021195835.png|319]]

但无论数据在不在 Cache 里面，每次写操作都会写回到内存，这样写操作将会花费大量的时间，无疑性能会受到很大的影响

## 总线嗅探

简单来说 就是A号CPU核心修改了 L1 Cache 中 i 变量的值，通过总线把这个事件广播通知给其他所有的核心，然后每个 CPU 核心都会监听总线上的广播事件，并检查是否有相同的数据在自己的 L1 Cache 里面，如果 B 号 CPU 核心的 L1 Cache 中有该数据，那么也需要把该数据更新到自己的 L1 Cache

但这个会一直监听和发出广播 会加重总线的负担

## MESI协议

Modified，已修改
Exclusive，独占
Shared，共享
Invalidated，已失效

# CPU如何执行任务

## 任务和程序的关系

程序运行 得到进程 进程内部包含多个线程
CPU调度器选择可运行的线程分配给CPU核心

而在Linux内核中 使用`task_struct`描述任务 
进程和线程都用`task_struct`来表示

**执行程序：关注 CPU 如何读取、解释和执行机器指令。
执行任务：关注操作系统如何安排线程使用 CPU，以及 CPU 如何在多个线程之间切换。**

接下来有两个方面的问题 即伪共享与CPU调度

## 伪共享

因为多个线程同时读写同一个 Cache Line 的不同变量时，而导致 CPU Cache 失效的现象称为伪共享（False Sharing）

这个可以参考MESI协议来理解 主要是会重复某些步骤

### 如何解决

解决办法包括缓存行对齐、填充字节，让频繁写入的变量分布在不同缓存行中。

例如 C++ 可以使用 `alignas(64)`，但具体大小需要根据硬件判断。

## CPU调度

|策略|用途|
|---|---|
|SCHED_FIFO|实时任务，按优先级及先进先出规则调度|
|SCHED_RR|实时任务，同优先级任务轮流执行|
|SCHED_DEADLINE|按任务截止期限进行调度|
|SCHED_NORMAL|普通任务|
|SCHED_BATCH|偏向批处理的任务|

这是几种常见的调度策略

# 软中断

Linux 系统为了解决中断处理程序执行过长和中断丢失的问题，将中断过程分成了两个阶段，分别是「上半部和下半部分」。  

上半部用来快速处理中断，一般会暂时关闭中断请求，主要负责处理跟硬件紧密相关或者时间敏感的事情。 

下半部用来延迟处理上半部未完成的工作，一般以「内核线程」的方式运行。


上半部直接处理硬件请求，也就是硬中断，主要是负责耗时短的工作，特点是快速执行； 

下半部是由内核触发，也就说软中断，主要是负责上半部未完成的工作，通常都是耗时比较长的事情，特点是延迟执行；
