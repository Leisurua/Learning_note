
程序所使用的内存地址叫做虚拟内存地址

实际存在硬件里面的空间地址叫做物理内存地址

而进程所持有的虚拟地址会通过CPU芯片中的MMU的映射关系 来转换成物理地址 接着来访问内存

而OS管理虚拟内存地址与物理地址之间的关系 有两种方式 分别是内存分段和内存分页


# OS与MMU的区别


**注：OS是软件 而MMU是硬件**

- **操作系统 (OS) 负责“管理与决策”（软件层面）：**
    
    - OS 负责为每个进程分配独立的虚拟地址空间。
        
    - OS 负责在内存中创建和维护**映射表**（如页表或段表），记录虚拟地址到物理地址的对应关系。
        
    - OS 负责处理各种内存异常（如内存不足时的页面置换、缺页异常等）。
        
- **内存管理单元 (MMU) 负责“执行转换”（硬件层面）：**
    
    - MMU 是集成在 CPU 芯片内部的硬件电路。
        
    - 它的唯一工作是在 CPU 执行程序的每一刻，**实时、高速地**将 CPU 发出的虚拟地址，通过查找 OS 建好的映射表，翻译成实际的物理地址。

- **OS 制定地图，MMU 按图索骥：** OS 就像是绘制地图的指挥中心，它把进程的“映射表”存放在物理内存中，并在进程切换时，把当前进程映射表的起始地址告诉 CPU（存入特定的寄存器）。当 CPU 访问虚拟地址时，MMU 会自动根据这个寄存器的指示去查表，完成地址转换，这个过程完全由硬件实现，速度极快，不需要 OS 介入。
    
- **MMU 遇到困难，OS 出面解决（异常处理）：** 如果 MMU 在查表时发现某个虚拟地址是非法的，或者该虚拟页当前不在物理内存中（被称为缺页异常/Page Fault），MMU 就会立刻阻断当前的内存访问，并触发一个硬件中断，将控制权交还给 OS。OS 接管后，会负责从硬盘把缺失的数据加载到物理内存中，更新映射表，然后让 MMU 重新执行刚才的转换。

接着开始介绍内存分段和内存分页


# 内存分段

程序是由若干个逻辑分段组成的，如可由代码分段、数据分段、栈段、堆段组成。不同的段是有不同的属性的，所以就用分段（Segmentation）的形式把这些段分离出来

在分段机制下 虚拟地址由**段选择子**和**段内偏移量**组成

而段选择子 又是由**段号**和**特权等标志位**组成

而段号 是作为**段表**的索引

而段表内部保存的是这个**段的基地址 段的界限和特权等级**等

虚拟地址中的段内偏移量应该位于 0 和段界限之间，如果段内偏移量是合法的，就将段基地址加上段内偏移量得到物理内存地址

这是其在物理内存中的样子

但是 分段存在两个问题：

内存碎片 和 内存交换效率低

前者很好理解 后者是在前者的基础上 为了解决外部内存碎片的问题 我们就会用到内存交换

内存交换的本质就是将内存写到硬盘上 然后再从硬盘上读回到内存中 也就是Linux中的Swap

因为硬盘的访问速度要比内存慢太多了，每一次内存交换，我们都需要把一大段连续的内存数据写到硬盘上。  所以，如果内存交换的时候，交换的是一个占内存空间很大的程序，这样整个机器都会显得卡顿。



# 内存分页

内存分页就是为了解决这个问题的

分页是把整个虚拟和物理内存空间切成一段段固定尺寸的大小。这样一个连续并且尺寸固定的内存空间，我们叫页（Page）。在 Linux 下，每一页的大小为 4KB

![[Pasted image 20261024002726.png]]

而虚拟地址与物理地址之间通过**页表**来映射

而页表 是存储在内存里的

而当进程访问的虚拟地址在页表中查不到时，系统会产生一个缺页异常，进入系统内核空间分配物理内存、更新进程页表，最后再返回用户空间，恢复进程的运行。[[虚拟内存#OS与MMU的区别]]

因为采取了分页 页与页之间是紧密排列的 所以没有外部碎片

但是 如果程序不足一页 但是我们最少最少也要分配出去一个页 那么就会造成内存浪费 也就是**内部内存碎片**

同样的 和分段一样 分页也会存在内存不足的问题 这时候的策略也是Swap 和之前的一样

但两这也有一点不同：

前面的 Swap（分段机制下的内存交换）：粒度大、效率低

这里的 Swap（分页机制下的换出/换入）：粒度小、效率高

因为这里，每次就交换少数几个几KB的页 数据量很小


接着我们再看虚拟地址与物理地址如何映射

虚拟地址分为两部分 **页号**和**页内偏移**

页号作为**页表**的索引

而页表包含了物理页每页所在物理内存的基地址

![[Pasted image 20261024003733.png]]


但是，普通的单级页表存在一个问题：如果虚拟地址空间很大，页表本身也会占用大量内存

为了解决这个问题 我们需要用到**多级页表**

## 多级页表

# 段页式内存管理

先将程序划分为多个有逻辑意义的段，也就是前面提到的分段机制； 

接着再把每个段划分为多个页，也就是对分段划分出来的连续空间，再划分固定大小的页；

这样，地址结构就由段号、段内页号和页内位移三部分组成

这时候 页只存在于虚拟地址中
