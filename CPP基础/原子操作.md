# `std::atomic`

原子≠无锁

通过`is_lock_free()`函数  可以判断这个原子操作是通过原子指令实现(返回`true`)  还是通过锁来实现(返回`false`)

`is_always_lock_free`是一个编译器常量 如果当前环境上的原子类型 X 是无锁类型 那么 `X::is_always_lock_free` 将返回 `true`

意思是 如果`std::atomic<int>::is_always_lock_free`的结果为`true` 那就代表：在当前编译目标下 所有`std::atomic<int>`对象都保证采用无锁实现

所以：`static_assert(std::atomic<int>::is_always_lock_free);`如果不满足 就直接编译失败

## 复制与移动

`std::atomic` 对象不可进行复制、移动、赋值

```cpp
atomic(const atomic&) = delete;
atomic& operator=(const atomic&) = delete;
operator T() const noexcept;
```

为什么？

如果允许
```cpp
std::atomic<int> b = a;
```

那么：
复制对象时，是否只读取当前值？
新对象是否具有独立的原子状态？
复制过程应该具有什么内存顺序语义？

C++没有提供这种操作 这个和[[mutex]]差不多

但是 可以把值读取后再写入 这是允许的


`std::atomic<T>`的这个T可以使用自定义类型 但必须满足三个条件：
可复制构造 可复制赋值 可平凡复制

因为原子操作本质上是对一块固定大小的内存来进行原子的读写 如果一个类型包含复杂的生命周期管理 那么在多线程中 无法包装原子性和安全性了


## `std::atomic_flag`

两个状态：`true`和`false`

`std::atomic_flag`做三件事：**销毁、清除、设置**
分别对应`clear()` `test_and_set` 销毁

其中`test_and_set`可以粗略地看作
```cpp
bool test_and_set()
{
    bool old = flag;
    flag = true;
    return old;
}
```


`std::atomic_flag`适合制作自旋锁
```cpp
class spinlock_mutex {
    std::atomic_flag flag{};
public:
    spinlock_mutex()noexcept = default;
    void lock()noexcept {
        while (flag.test_and_set(std::memory_order_acquire));
    }

    void unlock()noexcept {
        flag.clear(std::memory_order_release);
    }
};
```

但一般不建议使用自旋锁 这样会浪费CPU

## `std::atomic<bool>`

```cpp
std::atomic<bool> b{ true };
b = false;
```

赋值操作 `b = false` 返回一个普通的 `bool` 值  而非`atomic<bool>&` 

首先回到原子对象的本身设计：不可复制 但是可以把普通bool的值填进去 

而在标准 C++ 中，普通变量（如 `int` 或 `bool`）的赋值运算符通常返回左值的引用

如果这个赋值操作返回了一个引用 那就必须显示的进行`load()`来获得里面的布尔值

这会导致两个问题：
额外的性能开销

潜在的竞争条件：
如：
```cpp
std::atomic<bool> b{ true };
// 假设 operator= 返回的是 atomic 引用：
auto& ref = (b = false);  // 1. 先写：原子性地写入 false
bool flag = ref.load();   // 2. 再读：必须显式（或隐式）调用 load() 重新从内存加载
```
在“写入操作”与“随后的读取操作”之间  可能已有其他线程修改了 `b` 的值  导致你拿到的 `flag` 并不是你刚才赋进去的值

### `compare_exchange_weak()`与`compare_exchange_strong()`

这是两种CAS的实现

```cpp
flag.compare_exchange_weak(expected, true)
```

大致可以理解为：
如果 flag == expected：
    flag = true
    返回 true

否则：
    expected = flag 当前的值
    返回 false

但是这种有可能出现”假失败“

所以这时候 就使用`compare_exchange_strong()`


## `std::atomic<std::shared_ptr>`

`std::shared_ptr` 在底层通常由两个指针组成：

 一个指向底层实际管理的数据对象（`get()` 返回的指针）

一个指向控制块（Control Block）

控制块：多个线程对同一个对象的`shared_ptr`进行拷贝、赋值、销毁时 实则是在操作这个引用计数
就是当前有多少个 `shared_ptr` 正在指向这个对象 控制块是多个`shared_ptr`共用


`shared_ptr` 变量实例本身：它是一个结构体 内部存放的是两个指针 这个是非线程安全的

指向对象：这个也是非线程安全的

所以 如果是同一个`shared_ptr`对象 那么是会出现实例本身非线程安全 
多个`shared_ptr`对象 实例本身就是线程安全的

但是 不管怎么样 指向对象始终是非线程安全的 这个时候只能使用`mutex`了
