
计算机可以用状态机（State Machine）来理解，而操作系统处在应用程序与硬件之间，通过系统调用和硬件机制构建计算环境

# 应用程序视角

状态机三要素：
1. 状态：程序当前的数据和执行位置
2. 初始状态：程序开始时的状态
3. 状态迁移：执行完一条语句后，程序如何变化

以C语言的简化版本为例子

程序状态＝全局变量+函数调用栈

## syscall

syscall（系统调用）是用户程序请求内核服务的接口

举个例子
```cpp
write(1, "Hello", 5);
```

调用 `write()` 这样的库函数，与 CPU 通过 `syscall` 指令进入内核，是两个不同的动作。 前者是程序员看到的函数接口，后者是底部实现内核服务请求的一种机制


# 操作系统视角

如果有A B C三个程序 如果没有OS 让其自己处理硬件访问 设备冲突和资源分配

而OS提供统一的使用方式 减少对大多数硬件细节的考虑

OS视角的状态机就是 管理多个程序的状态
而且OS本质上也是一种程序 也可以使用第一种来解释



# 硬件视角

CPU也是状态机

硬件状态≈寄存器+内存

基本可以理解为：取指令 → 译码 → 执行 → 更新状态

Reset ： 

CPU Reset 会使处理器进入架构规定的初始状态，并从规定位置执行指令。

操作系统也是从这种硬件机制提供的起点逐渐启动起来的，过程中可能经过固件和引导程序。

Interrupt：

计算机存在中断机制，比如定时器中断。中断到来且允许响应时，CPU 可以转去执行内核中的中断处理程序

所以，普通用户程序出现死循环，并不意味着整台计算机必然无法运行其他任务。

中断机制配合处理器的特权机制，使内核有机会重新获得 CPU 的控制权

多核处理器：

- 每个 CPU 核心具有自己的寄存器与执行状态。
- 多个核心能够访问共享内存。
- 不同核心的执行可能交错，也可能同时发生。

# 一个例子

```go
fmt.Println("Hello")
```

应用程序视角：Go 程序执行函数，最终请求写入标准输出

操作系统视角：内核处理写入请求，将数据交给相应的对象和设备机制

硬件视角：CPU 执行机器指令，硬件最终完成相关数据传输和输出
