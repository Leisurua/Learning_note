
先回忆Hanoi的例子

有两种写法：

A
```cpp
#include <iostream>

// move 函数用于打印移动过程
void move(int disk, char from, char to) {
    std::cout << "Move disk " << disk << " from " << from << " to " << to << std::endl;
}

// 递归实现汉诺塔
// n: 盘子数量，from: 起始柱，aux: 辅助柱，to: 目标柱
void hanoiRecursive(int n, char from, char aux, char to) {
    if (n == 1) {
        move(1, from, to);
        return;
    }
    // 1. 将 n-1 个盘子从 from 移动到 aux，借助 to
    hanoiRecursive(n - 1, from, to, aux);
    
    // 2. 将第 n 个盘子从 from 移动到 to
    move(n, from, to);
    
    // 3. 将 n-1 个盘子从 aux 移动到 to，借助 from
    hanoiRecursive(n - 1, aux, from, to);
}

int main() {
    int n = 3; // 盘子数量
    std::cout << "--- 递归写法结果 (3个盘子) ---" << std::endl;
    hanoiRecursive(n, 'A', 'B', 'C');
    return 0;
}

```

B
```cpp
#include <iostream>
#include <stack>

// 定义一个结构体来存储每一步的状态
struct Command {
    int n;       // 当前盘子数量
    char from;   // 起始柱
    char aux;    // 辅助柱
    char to;     // 目标柱
    bool isMove; // true 表示直接移动盘子，false 表示需要继续分解
};

// 非递归实现汉诺塔（使用显式栈）
void hanoiIterative(int n, char from, char aux, char to) {
    std::stack<Command> st;
    
    // 初始命令入栈
    st.push({n, from, aux, to, false});
    
    while (!st.empty()) {
        Command cmd = st.top();
        st.pop();
        
        if (cmd.n == 0) continue;
        
        if (cmd.isMove) {
            // 如果是直接移动指令，打印结果
            std::cout << "Move disk " << cmd.n << " from " << cmd.from << " to " << cmd.to << std::endl;
        } else {
            // 根据栈的后进先出（LIFO）特性，入栈顺序需要与递归调用顺序相反：
            
            // 对应递归第3步：hanoiRecursive(n - 1, aux, from, to);
            st.push({cmd.n - 1, cmd.aux, cmd.from, cmd.to, false});
            
            // 对应递归第2步：move(n, from, to);
            st.push({cmd.n, cmd.from, cmd.aux, cmd.to, true});
            
            // 对应递归第1步：hanoiRecursive(n - 1, from, to, aux);
            st.push({cmd.n - 1, cmd.from, cmd.to, cmd.aux, false});
        }
    }
}

int main() {
    int n = 3; // 盘子数量
    std::cout << "--- 非递归（栈模拟）写法结果 (3个盘子) ---" << std::endl;
    hanoiIterative(n, 'A', 'B', 'C');
    return 0;
}

```

显然 这里是我们通过模拟stack来写的

那么 类比一下 我们也可以模拟一种情况：即使只有一个 CPU，没有操作系统，也没有多线程库，我们仍然可以让两个死循环程序交替执行，产生它们好像在同时运行的效果


# CrazyOS

核心代码
```cpp
while (1) {
    p = pickup_one();
    p->single_step();
}
```

意思是 选择一个程序 让这个程序只执行一条指令

**程序下一时刻的状态，由当前状态和当前执行的指令决定**

假设有两个程序P1和P2

P1: A1 → A2 → A3 → A4 → ...
P2: B1 → B2 → B3 → B4 → ...

CrazyOS可以安排成：

时间 →

P1: A1      A2      A3      A4
P2:     B1      B2      B3      B4

同时每个程序要保有现在的状态 这样重新运行这个程序时 才知道从哪里恢复

# 进程

以某个程序`a.out`为例

- 程序：磁盘上的 `a.out`，包含机器指令、初始化数据等。
- 进程：操作系统加载并运行 `a.out` 后，创建的运行实例，拥有自己的执行状态和操作系统管理信息。

一个程序可以对应多个进程
每个进程的PC 寄存器 变量值也可以不同

- 程序：规定计算机应该执行哪些指令，以及这些指令的行为。
- 进程：拥有具体的运行状态 \(S_t\)，并随着指令执行不断改变状态。

## 进程包含内容

|组成|作用|
|---|---|
|代码与数据|程序的指令、全局变量等|
|虚拟地址空间|进程使用的内存地址空间|
|PC、寄存器|记录执行位置与计算状态（具体由线程持有）|
|栈、堆|函数调用和动态内存分配|
|打开的文件|文件描述符及相关资源|
|PID|操作系统用于标识进程的编号|
|进程管理信息|调度、状态、资源管理等信息|

## 进程与线程的区别

进程面向内存与其他系统资源 线程面向cpu/寄存器

而一个进程中可以有多个线程 这些线程共享所属进程的内存空间和全局变量，但有自己的栈、寄存器和程序计数器

`fork()` 之后，父子进程有各自的虚拟地址空间。即使变量最初的值相同，修改也不会影响另一个进程。

```c
pid_t pid = fork();

if (pid == 0) {
    // 子进程
} else if (pid > 0) {
    // 父进程
} else {
    // 创建失败
}
```
可以通过fork()的返回值判断是父进程还是子进程

## 进程树

根据`fork()`的方法 我们不难发现创建出来的线程具有父子关系 （实际上`spawn`也是）
```
        A
      /   \
     B     C
    / \     \
   D   E     F      每个节点都是 fork 出来的

```

那么我们也可以通过树有关的性质来理解其父子关系

执行了几次`fork()` 一共就有$2^N$个进程
但是带了条件的`fork()`不能简单的使用这个公式

如果有N个进程 且所有进程都来自同一个初始进程 那么
**父子关系边数=$N-1$**


### 孤儿与托孤

一般出现这种情况 是因为出现了父亲先退出（父进程终止运行）

通常情况下 孤儿会被重新指定父进程，通常由 PID 1 对应的进程，或某个被指定为 subreaper 的进程收养 

当然，孤儿往 1 号进程发任何信息，1 号进程一概不管，直接忽略掉

但是 **进程退出后 节点不一定会立即消失** 即僵尸进程：子进程已经停止执行，但内核仍然保留必要的退出信息，等待父进程读取。

所以，从进程树的角度看，进程终止和进程被回收是两个不同的事件


## 缓冲区

先看NJUOS26spring的原文
```
终端上数出来是 6 个，和推导一致，`wc` 之类的计数也没有任何问题。但换个统计方式——把输出接进管道、或者写进文件——数字就变成 8 了。
```

看一下原文的代码
```c
for (int i = 0; i < 2; i++) {
    fork();
    printf("Hello\n");
}
```

这是因为我们假设：`printf("Hello\n");`执行后文字立刻出现在终端或文件里 但是 `printf`管理着一个用户态输出缓冲区

意思就是：`printf()` 执行了，不代表已经调用 `write()` 将文字交给内核。

一般来说 对于输出到终端 使用的是行缓存
而输出到文件或管道 使用的是全缓冲

第一次循环中两个进程执行 `printf` 后，缓冲区中的内容可能还没有写出

## execve

在原来的fork()中 产生的进程也仍然运行原来的程序代码

而`execve()` 的作用是：把当前进程的程序映像替换成另一个可执行程序，并开始执行新程序

注意：
   `execve()` 不创建新进程，进程 PID 保持不变。
   `execve()` 成功后，原程序的代码不会再继续执行，因此不会返回到原来的调用位置。

## exit

与fork 复制、execve 复位类似 exit代表销毁


# 进程的地址空间

进程地址空间（address space）是操作系统为每个进程提供的一套独立的、连续的虚拟内存地址范围，因此也叫虚拟地址空间。
