# 创建线程

一般的 通过`std::thread`来创建线程
创建线程后 需要在线程对象生命周期结束前决定执行策略 即`join()`和`detach()`
通常我们都调用`join()` 否则则有可能发生未定义行为


还需要注意的是 若程序在某一步抛出异常而终止 那么就要在异常处理中调用`join()` 从而避免析构出现问题
不过一般的 我们在`catch`中调用一个`join()` 而在`try`中不调用 因为我们是要**一些当前线程可能抛出的异常** `try` `catch` 是为了让线程正确执行完毕和对象正确析构 不掩盖错误 `try`的代码抛出异常被`catch`接住了 这时候再抛出和调用`join()`
```cpp
struct func;
void f(){
    int n = 0;
    std::thread t{ func{n},10 };
    try{
        // todo.. 一些当前线程可能抛出异常的代码
        f2();
    }
    catch (...){
        t.join(); // 1
        throw;
    }
    t.join();    // 2
}
```

# 线程参数的传递

这一块比较复杂 也经常搞不懂 所以记录详细一点
前置理解：[[栈与堆]] [[引用与复制]]

首先记住一点：**传入``std::thread``的参数默认都是按值复制（Copy）的

即使目标线程函数的形参类型被声明为引用

```cpp
void f(int, const int& a);

int n = 1;
std::thread t{ f, 3, n };
```

这样会出现一个问题：如果我们的 f 的形参类型不是 **const 的引用** 则会产生一个编译错误

这是因为 C++ 语法严格禁止将**非常量左值引用（`int&`）绑定到右值（临时对象） 但是常量左值引用(`const int&`)则可以**

解决办法：`std::ref` `std::cref`

`std::ref`可以返回一个包装类 `std::reference_wrapper` 然后简单的来说 这个类可以隐式转化成被包装对象的引用 “cref”的“c”就是“const”的意思

## 成员函数指针

**成员函数指针**也是可调用的  可以传递给 `std::thread` 作为构造参数 让其关联的线程执行成员函数

传入成员函数指针、与其配合使用的对象、调用成员函数的参数 构造线程对象`t` 启动线程

```cpp
struct X{
    void task_run(int)const;
};

 X x;
 int n = 0;
 std::thread t{ &X::task_run,&x,n };
 t.join();
```

这个在这里只是简单的提一下 详细要见[[thread的源码解析]]

# `std::thread`转移所有权

先简单理解两个概念：
线程资源 = 真正在操作系统里运行的东西 
线程对象 = C++ 用来管理这个线程资源的对象

`std::thread`不可复制 两个`std::thread`对象不可以表示同一个线程 但是可以通过移动构造或移动赋值来进行线程资源所有权的转移

注意 `std::move`不是把线程搬了也不是复制 而是类似于调用`std::thread`的移动构造函数

还有 举个例子
```cpp
std::thread f(){
    std::thread t{ [] {} };
    return t;
}

int main(){
    std::thread rt = f();
    rt.join();
}
```
其中的`return`出来的`t`其实和`std::move`出来的类型一样 都是右值 所以都可以用来所有权的转移

# `std::jthread`

`std::jthread` 相比于 C++11 引入的 `std::thread` 只是多了两个功能：

1. **RAII 管理**：在析构时自动调用 `join()`
2. **线程停止功能**：线程的取消/停止

## 线程停止

核心一句话：**不是强行杀死子线程 而是通过“发信号+检查” 主线程发出一个“请停止”的信号 子线程在安全地方主动去检查这个请求 最后优雅退出**


三个核心组件：
`std::stop_source` `std::stop_token` `request_stop`
分别发送请求 查询 请求停止
