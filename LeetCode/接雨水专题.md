
# 二维接雨水

![[QQ20261022-154728.png|485]]

这道题一开始我是想着用双指针 从左向右开始查找是否有`height[fast]＞=height[slow]` 然后把每次的加起来 最后再从右往左来一次 最后两次相加

大体代码是这样的：
```cpp
class Solution {
public:
    int trap(vector<int>& height) {
        int n = height.size();
        if (n <= 2) return 0; // 柱子少于3根接不到水

        int total_water = 0;
        int slow = 0;
        int block_sum = 0; // 记录 slow 和 fast 之间经过的柱子高度和

        // 1. 从左向右遍历（结算最高峰左侧的所有雨水）
        for (int fast = 1; fast < n; ++fast) {
            if (height[fast] >= height[slow]) {
                // 计算区间水量：按照 slow 的高度计算矩形面积 - 内部柱子体积
                total_water += height[slow] * (fast - slow - 1) - block_sum;
                slow = fast;   // 更新基准点
                block_sum = 0; // 重置区间柱子高度和
            } else {
                block_sum += height[fast]; // 还没找到更高的边界，把经过的柱子加起来
            }
        }

        // 此时 slow 停留在从左往右看到的“最高峰”的索引位置
        int max_idx = slow;

        // 2. 从右向左遍历（结算最高峰右侧的所有雨水）
        slow = n - 1;
        block_sum = 0;
        // 注意：fast 只需要走到 max_idx 就可以停止了，避免最高峰处重复计算
        for (int fast = n - 2; fast >= max_idx; --fast) {
            if (height[fast] >= height[slow]) {
                // 计算区间水量：按照 slow 的高度计算矩形面积 - 内部柱子体积
                total_water += height[slow] * (slow - fast - 1) - block_sum;
                slow = fast;   // 更新基准点
                block_sum = 0; // 重置区间柱子高度和
            } else {
                block_sum += height[fast]; // 记录经过的柱子
            }
        }

        return total_water;
    }
};
```

可以说 这种方法更符合直觉 同时效率是O(n) LeetCode实测和标准解法都是击败100%

但是问题在于要维护边界条件较多

再看标准解法
```cpp
class Solution {
public:
    int trap(vector<int>& height) {
        int left=0;
        int right=height.size()-1;
        int leftmax=0;
        int rightmax=0;
        int total=0;
        while(left<right){
            if(height[left]<height[right]){
            if(height[left]>=leftmax){
                leftmax=height[left];
            }
            else{
                total+=leftmax-height[left];
            }
            left++;
        }
        else{
            if(height[right]>=rightmax){
                rightmax=height[right];
            }
            else{
                total+=rightmax-height[right];
            }
            right--;
        }
        }
        return total;
    }
};
```

这种解法代码量更小 而且边界情况更好处理
但并不属于直觉一下子就能想出来

我们设置了`left`和`right`两个指针
我们先看 如果这两者之间有一种更小 那么水量就是由较小的那一方来决定

这时候 较小的一方的有一侧肯定是已经被挡住了（也就是较大的那一方）
所以此时只要比较较小的一侧 与 这一侧的已保留的最大值 就可以判断这里能不能接水 然后同理以此类推
