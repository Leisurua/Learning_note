# 网络协议

以常用的TCP/IP为例

应用层 HTTP，DNS，SMTP  规定应用程序如何交换信息
传输层 TCP，UDP  负责进程之间的数据传输
网络层 IP ICMP  负责跨网络寻址与转发
链路层 Ethernet，WIFI  负责同一链路上的帧传输


以一个Go Gin的例子
```go
r := gin.Default()

r.GET("/hello", func(c *gin.Context) {
    c.JSON(200, gin.H{
        "message": "hello",
    })
})

r.Run(":8080")
```

|协议|在这个例子中的作用|
|---|---|
|HTTP|规定 GET 请求与响应格式|
|TCP|在客户端和服务器进程之间传输字节|
|IP|负责主机寻址（此处使用本机回环地址）|
|Ethernet|如果通过以太网通信，会负责链路上的帧传输；本机回环通信不需要经过以太网|

简单来说 HTTP 解决应用之间如何交流，TCP 解决数据如何可靠传输，IP 解决数据发往哪里，以太网解决本地链路如何传送数据

IP 地址：定位网络中的目标主机或网络接口。
端口号：确定目标主机上的通信端点。
TCP / UDP：规定进程之间如何传输数据。
Socket：应用程序使用操作系统网络通信功能的接口。

### IP：

IP（Internet Protocol，网际协议）提供：

Basic naming scheme：通过 IP 地址标识网络接口，帮助定位目标主机。
Unreliable delivery：尽力交付数据，但不保证数据一定到达。
Datagram：以数据报（Packet）为单位传输。
Host-to-Host：负责将数据从一台主机送往另一台主机。

IP 能根据目标 IP 地址转发数据包，但无法保证：

数据包不丢失。
数据包按照发送顺序到达。
数据包不会重复到达。

而且，IP 本身不负责确定数据应该交给目标主机上的哪个应用进程。


### UDP

UDP（User Datagram Protocol，用户数据报协议）建立在 IP 之上

UDP 相比 IP 增加了：
源端口号、目标端口号。
数据报边界。
校验和，用于检测传输错误。

但 UDP 仍然不保证数据到达，也不保证顺序。


### TCP

TCP（Transmission Control Protocol，传输控制协议）也建立在 IP 之上。

但它提供三个重要特性：

① Reliable（可靠）

TCP 通过序列号、确认应答、超时重传等机制，保证成功交付给应用的数据按序且不重复。
如果连接发生无法恢复的故障，TCP 会报告错误，不能保证任何故障下都完成传输。

② Byte Stream（字节流）

TCP 传输的是连续的字节序列
TCP 不保留应用程序每次 send 的消息边界

③ Connection（连接）

最典型的就是**三次握手**
#### 三次握手

![[Pasted image 20261011212341.png|476]]

第一次握手：客户端发送SYN
SYN=1  请求建立TCP连接
seq=x  客户端选择初始序列号x
客户端由CLOSED进入SYN_SENT状态

第二次握手：服务端发送SYN+ACK
SYN=1  服务器也发送自己的初始序列号
ACK=1  确认号字段有效
seq=y  服务器的初始序列号
ack=x+1  确认客户端的 SYN，并表示期待客户端下一个序列号为 x+1
服务器进入 `SYN_RCVD` 状态

第三次握手：客户端发送 ACK
ACK = 1
seq = x + 1
ack = y + 1
表示客户端已经收到服务器的 SYN。
此时客户端进入 `ESTABLISHED` 状态。
服务器收到第三次握手的 ACK 后，也进入 `ESTABLISHED` 状态。
双方可以开始进行 TCP 数据传输。
